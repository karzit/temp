# 노트북 서술 규칙 (집필용)

이 문서는 **노트북을 쓰는 사람**을 위한 것입니다. 학습자는 읽지 않아도 됩니다.

목표는 하나입니다. **강사가 옆에 없어도 혼자 끝까지 갈 수 있게 만든다.**
지금까지의 노트북은 "무엇을 가르칠 것인가"는 정리되어 있었지만 "어떻게 이해시킬 것인가"가
비어 있었습니다. 그 빈칸을 메우는 규칙입니다.

---

## 1. 노트북 전체 골격 — 6단계

모든 노트북(과 노트북 안의 각 주제)은 이 순서를 따릅니다.

| 단계 | 무엇을 쓰나 | 빠지면 생기는 일 |
|---|---|---|
| ① 문제 | 이 기술이 없으면 무엇이 안 되는가 | "이걸 왜 배우지?"가 끝까지 남는다 |
| ② 직관 | 일상적인 비유 한 개 | 정의를 외우기만 하고 감이 안 온다 |
| ③ 개념 | 정확한 정의·수식 | 비유만 남고 실제로는 못 쓴다 |
| ④ 코드 | 최소 예제부터 한 단계씩 | 완성 코드를 복사만 하게 된다 |
| ⑤ 동작 과정 | 데이터가 어떻게 흘러가는지 | 코드가 블랙박스로 남는다 |
| ⑥ 실습·해석 | 직접 바꿔보기 + 결과 읽는 법 | 실행은 했는데 뭘 봤는지 모른다 |

**개념부터 시작하지 않습니다. 항상 문제부터 시작합니다.**

```
❌  # 임베딩
    임베딩이란 텍스트를 벡터로 바꾸는 것입니다. ...

⭕  문서가 100만 개 있습니다. "환불 규정"을 찾고 싶습니다.
    그런데 컴퓨터는 글의 '의미'를 모릅니다. 글자가 하나도 안 겹치는
    "반품 절차" 문서를 찾아줄 방법이 없습니다.
    그래서 등장한 것이 임베딩입니다.
```

## 2. 노트북 첫 셀에 반드시 들어가는 것

```markdown
[Colab 배지]

# NN. 제목

> 원본 강의: ...   (있는 경우)

## 이 장을 배우는 이유

<문제 상황 3~5줄. "우리는 지금 ...을 하고 싶습니다. 그런데 ...가 안 됩니다.
이 문제를 푸는 것이 이번 장의 주제입니다.">

이번 장에서 배우는 것
- 왜 X가 필요한지
- X가 어떻게 동작하는지
- 직접 구현하는 방법

## 이 노트북을 읽는 법
<기존 안내 유지 + 소요 시간, 오래 걸리는 셀 안내>
```

## 3. 코드 셀 규칙

### 3-1. 한 셀에는 한 가지 일만

10~20줄짜리 셀 하나에 로드·전처리·학습·평가를 다 넣지 않습니다. 학습자는
어느 줄에서 무엇이 바뀌었는지 추적하지 못하고 `Shift+Enter`만 누르게 됩니다.

```
❌  한 셀:  데이터 생성 + 초기화 + 200번 학습 루프 + 결과 출력
⭕  다섯 셀: 데이터 보기 → 직선 하나 그어보기 → 얼마나 틀렸나 재기
             → 한 번만 고쳐보기 → 그제서야 200번 반복
```

### 3-2. 코드 셀 **앞**에는 "지금 무엇을 할 건지"

```
❌  Gradient Descent를 numpy로 구현해봅시다.

⭕  지금부터 공부 시간(x)으로 시험 점수(y)를 예측하는 직선을 찾습니다.
    W와 b를 0에서 시작해 200번 반복하면서 cost가 줄어드는지 봅니다.
    잘 되면 W는 2, b는 3 근처에서 멈춥니다.
```

### 3-3. 코드 셀 **뒤**에는 "결과를 어떻게 읽는지"

출력이 나왔는데 그게 좋은 건지 나쁜 건지 학습자는 모릅니다. 반드시 적어줍니다.

```
⭕  정확도 0.85가 나왔다면 100개 중 85개를 맞혔다는 뜻입니다.
    - cost가 계속 줄어들면 정상입니다.
    - cost가 오히려 커진다면 `lr`이 너무 큽니다. 0.001로 낮춰보세요.
    - W가 2 근처로 가지 않으면 반복 횟수(`epochs`)가 부족한 것입니다.
```

**틀렸을 때 무엇을 의심해야 하는지**까지 적는 것이 핵심입니다.

### 3-6. 새 라이브러리·객체는 처음 쓸 때 한 문단 설명

## 4. 용어

- 처음 나오는 용어는 **그 자리에서 한 문장**으로 풀어줍니다. 용어집 링크만 걸고 넘어가지 않습니다.
  > 학습률(learning rate): 한 번에 얼마나 크게 움직일지 정하는 값.
  > 크면 목표를 지나쳐 버리고, 작으면 너무 천천히 갑니다.

## 6. 문장은 소리 내어 읽어보고 쓴다

설명을 늘리다 보면 번역투가 섞이기 쉽습니다. 어색하면 학습자는 두 번 읽어야 하고,
그 순간 흐름이 끊깁니다. 아래 세 가지만 걸러도 대부분 잡힙니다.

**① 명사 앞에 관형절을 길게 붙이지 않습니다.** 한국어는 뒤에서 앞으로 읽어야 해서 걸립니다.

```
❌  정답을 우리가 아는 데이터를 일부러 만듭니다.
⭕  답을 미리 정해놓고 데이터를 만듭니다.

❌  이번에도 정답 규칙을 우리가 압니다.
⭕  이번에도 답을 미리 정해놓았습니다.
```

**② 같은 조사가 한 문장에 겹치지 않게 합니다.**

```
❌  그 숫자를 데이터를 보고 컴퓨터가 스스로 정하게 만드는 것
⭕  데이터를 보고 그 숫자를 컴퓨터가 스스로 정하게 만드는 것
```

**③ 주어와 서술어를 맞춥니다.** 문장이 길어지면 중간에 주어가 바뀝니다.

```
❌  짙은 안개 속 산비탈에 서 있고, 골짜기 바닥으로 내려가야 합니다.
⭕  짙은 안개 속 산비탈에 서 있다고 해봅시다. 골짜기 바닥까지 내려가야 하는데
    주변이 하나도 보이지 않습니다.

❌  W를 조금 바꿨을 때 결과가 얼마나 흔들리는지는 x가 클수록 커집니다.
⭕  W를 조금 바꿨을 때 결과가 흔들리는 정도는 x가 클수록 커집니다.
```

한 문장이 두 줄을 넘어가면 대개 두 문장으로 쪼개는 편이 낫습니다.

- 실제보다 친절한 척하지 않습니다. 수식을 안 가르치면 "안 가르친다"고 적습니다.
