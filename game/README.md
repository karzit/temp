# 바로벤토 (게임판)

노트북과 같은 내용을 **직접 만져보며** 익히는 브라우저 게임입니다. 노트북을 대체하지 않습니다 —
같은 개념을 손으로 굴려본 뒤 노트북에서 코드로 확인하는 쪽이 빠른 사람을 위한 다른 통로입니다.

## 실행

Pyodide(브라우저 안 파이썬)를 쓰기 때문에 `index.html`을 더블클릭하면 동작하지 않습니다.
저장소 루트에서 웹 서버를 하나 띄우세요.

```bash
python -m http.server 8000
```

그리고 브라우저에서 http://localhost:8000/game/ 를 엽니다.

파이썬(10MB 남짓)은 **페이지에 들어오는 순간부터 뒤에서 내려받습니다.** 소개 문구를 읽고 메일을
확인하고 사무실에 들어가는 동안 대개 준비가 끝나서, 첫 실행에서 기다릴 일이 없습니다.
▶ 실행을 눌렀는데도 아직 안 끝났을 때만 아래에 진행 막대가 나타납니다.
받는 데 실패해도 게임은 계속 돌아가고, 실행할 때 다시 시도합니다.

진행 상황은 브라우저 `localStorage`에만 저장되고, 우측 하단 "처음부터"로 지웁니다.
만든 파일도 함께 저장됩니다. 다음 날은 전날 폴더 위에서 시작하고, 그 장의 의뢰서와
참고 문서만 새로 깔립니다.

하루 도중에 새로고침하면 그날은 처음부터 다시 재생됩니다. 전날까지 만든 파일은 그대로 있고,
그날 받은 연습·실습 파일은 처음 받았을 때의 내용으로 다시 깔립니다.

## 세계관

먼 미래. 고장난 인공지능을 고치는 회사 **바로벤토**. 플레이어는 신입 **깁스 W 토이비**이고,
사내 지원 AI **Aistb**가 옆에 붙습니다. 세계관과 오프닝 원문, 장 구성과 각 장 일기에 심어둔 떡밥은
[앞으로.md](앞으로.md), 이름의 유래는 [gmae-tmi.md](gmae-tmi.md)에 있습니다. 대본을 쓸 때는 그쪽이 기준입니다.

## 화면 구성

게임은 씬 단위로 넘어갑니다. 챕터가 `scenes: ["intro", "phone", "room", "desk"]` 처럼 순서를 정합니다.

| 씬 | 화면 |
|---|---|
| `intro` | 소개 문구와 "시작하기" |
| `phone` | 세로로 꽉 찬 휴대폰. 메일에서 빠져나오면 시선이 위로 올라가고 문이 보임 → 문을 누르면 입장 |
| `room` | 불 꺼진 방. 모니터만 켜져 있고, 누르면 화면을 채움 |
| `desk` | 모니터 안. 코드 에디터 + Aistb |
| `diary` | 하루가 끝나면 나오는 토이비의 일기. "다음날로"로 다음 챕터. 마지막 장은 아래에 크레딧과 노트북 안내(`notes`)가 붙는다 |

`desk`가 이 게임의 본체입니다.

- **에디터**([js/ide.js](js/ide.js)) — 왼쪽 탐색기, 탭, 편집창, 아래 실행 결과.
  탐색기에서 폴더/파일을 만들고, 행에 커서를 올리면 나오는 `×`로 지웁니다(의뢰서는 지울 수 없습니다).
  탭은 눌러서 고르고 `×`로 닫으며, **끌어서 순서를 바꾸거나 반대쪽 화면으로 옮길 수 있습니다**
  (같은 파일이 양쪽에 열려 있으면 한 자리로 합쳐지고, 옮긴 뒤 빈 화면이 남으면 분할이 접힙니다).
  탭 오른쪽 `◫`로 화면을 둘로 나눠 의뢰서를 띄워두고 코드를 짤 수 있습니다.
  편집창과 결과 창 사이의 손잡이를 끌면 결과 창 높이가 바뀌고, 두 번 누르면 기본 높이로 돌아갑니다.
- **한 문장씩 실행**([js/python.js](js/python.js)) — `↓ 한 줄`은 문장 하나만, `▶ 실행`은 중단점까지
  (없으면 끝까지) 갑니다. 줄 번호를 누르면 **중단점**이 생기고, 다음에 실행될 줄은 왼쪽에 파랗게
  표시됩니다. `↺` 는 처음부터 다시입니다. 변수는 문장 사이에 그대로 이어집니다.

  > 편집창 영역의 클릭 처리는 `mousedown`에서 화면을 다시 그리지 않도록 되어 있습니다.
  > 다시 그리면 누른 요소가 사라져 클릭이 완성되지 않습니다(탭 선택·닫기·분할이 전부 먹지 않게 됩니다).
- **자동완성**([js/complete.js](js/complete.js)) — 주피터와 같은 방식입니다. 두 글자를 치거나
  `np.` 처럼 점을 찍으면 목록이 뜨고, `Tab`·`Ctrl+Space`로 직접 열 수도 있습니다.
  `↑↓` 로 고르고 `Enter`/`Tab` 으로 넣고 `Esc` 로 닫습니다.
  후보는 **실행 중인 세션**([js/python.js](js/python.js)의 `completeNames`)에 실제로 있는 이름입니다 —
  한 문장이라도 돌린 뒤에는 그때 만든 변수와 `dir(np)` 가 그대로 나옵니다.
  아직 아무것도 안 돌렸으면 파일에 나온 이름과 기본 낱말로 대신합니다.
  낱말이 없을 때의 `Tab` 은 네 칸 들여쓰기(`Shift+Tab` 은 반대), `Enter` 는 앞줄의 들여쓰기를
  이어 주고 `:` 뒤에서는 한 단 더 들어갑니다.

  > 편집창을 고칠 때는 `value` 를 직접 갈아 끼우지 말고 `Complete.replace` 를 쓰세요.
  > `execCommand("insertText")` 로 넣어야 브라우저의 되돌리기(`Ctrl+Z`)가 살아 있습니다.
  > 목록 상자의 자리는 손으로 계산하므로, 편집창은 `wrap="off"`(줄 안 접힘)를 전제합니다.
- **Aistb**([js/aistb.js](js/aistb.js)) — 우측 하단 상주. 말풍선으로 말하고, 누르면 업무 메뉴
  (의뢰 확인 · 완료 보고 · 지금 할 일 다시 듣기 · 환경설정 · 업무 종료)가 열립니다.
  실행이 실패하거나 한동안 조작이 없으면 먼저 말을 겁니다.
- **파일**([js/fs.js](js/fs.js)) — 브라우저 메모리 안의 가상 폴더입니다. 의뢰서도 여기 파일로
  들어 있어서 언제든 다시 열 수 있습니다. 실행할 때마다 같은 경로로 파이썬 쪽에도 옮겨 심으므로,
  코드에서 `pd.read_csv("work/자료/○○.csv")` 처럼 탐색기에 보이는 그대로 읽으면 됩니다.
- **그림**([js/python.js](js/python.js)) — `matplotlib` 으로 그린 것은 결과 창 글자 아래에 붙습니다.
  문장 하나가 끝날 때마다 열려 있는 그림을 다시 거둬오므로, `plt.scatter(...)` 다음 줄에서
  제목을 붙이면 같은 그림이 갱신됩니다. 처음 그릴 때만 도구와 한글 폰트를 받느라 몇 초 걸립니다.
  `plt.show()` 를 써도 되고(경고 없이 무시됩니다), 그림 색은 작업 단말의 어두운 화면에 맞춰집니다.

  > 한글 폰트(나눔고딕)는 그림을 처음 그리는 순간 CDN에서 받아 등록합니다. 못 받으면 그림은
  > 그대로 나오고 한글만 네모가 됩니다.

무엇을 기다리는지 알아냅니다(몇 번째 문장까지인지는 이분 탐색). 알아보지 못한 조건은
짐작하지 않고 함수를 그대로 보여줍니다.

## 챕터 쓰는 법

`content/ch00.js`가 예시입니다. 챕터 하나가 파일 하나이고, `js/app.js`의 `CHAPTERS`에 넣으면 됩니다.

```js
id: "ch00", title: "0 · 튜토리얼",
decay: 0,                                              // Aistb 고장 단계(0~4). 없으면 0
voice: "self",                                         // 종장 전용. 화자를 토이비 독백으로 바꾼다
scenes: ["desk", "diary"],
desk: {
  files: [{ path, content, readOnly, kind: "brief" }],  // 시작할 때 깔아둘 파일
  beats: [{ lines, spot, wait, menu, reject, nudge }],
  report: function () { return 문제이유 || null; },
  idleLines: [], errorLines: [],
},
diary: ["...", ""],                                    // 한 줄에 한 문장. 빈 줄이 문단을 나누고 그 사이는 이어 붙어 보인다
notes: ["...", ""],                                    // 일기 아래 게임 밖 주석. 28장만 씀
endLabel: "마치기",                                     // 일기 버튼 글자. 없으면 "다음날로"
```

대사와 일기에 쓸 수 있는 표시는 `**굵게**`, `~~취소선~~`, `[글자](주소)` 셋입니다
(`js/scenes.js`의 `rich`). 주소는 `http`/`https`만 받습니다.

`notes`는 **토이비가 쓴 것이 아닙니다.** 일기 아래에 선을 긋고 한 단계 흐리게 붙는,
게임 밖에서 다는 주석입니다. 지금은 28장에만 있고 엔딩 크레딧과
**게임이 손으로 정해 주고 넘어간 자리들**(18장 필터·20장 Q·22장 사내모델)이
원래는 어떻게 되는지를 노트북 링크로 알려 줍니다. 세계관을 지키느라 게임 안에서는
"실제로는 학습으로 찾아냅니다" 까지만 말하고 지나가므로, 그 다음을 여기서 갚습니다.

`decay` 는 챕터 하나에 하나입니다. 숫자가 커질수록 Aistb 의 눈이 자주, 오래 빨개지고,
**하려던 말 사이사이에 엉뚱한 말이 끼어듭니다**(`js/glitch.js`).
자리를 손으로 잡지 않습니다 — 굴려서 넣기 때문에 같은 장을 두 번 해도 다른 데서 나옵니다.

| 단계 | 줄 하나마다 끼어들 확률 |
|---|---|
| 0 | 0 (안 나옴) |
| 1 | 0.05 |
| 2 | 0.10 |
| 3 | 0.18 |
| 4 | 0.35 |

**끼워 넣기이지 덮어쓰기가 아닙니다.** 10~25장의 Aistb 는 아직 가르치는 중이라
대사를 덮으면 수업이 깨집니다. 첫 줄 앞과 마지막 줄 뒤에는 넣지 않습니다 —
그 두 자리는 플레이어가 상황을 잡는 자리입니다.
대본(`대본.md`)에는 안 들어갑니다. 정해진 것이 아니기 때문입니다.

(`js/aistb.js` 의 `setDecay`, `css/style.css` 의 `.aistb.decay-N`).
**말투가 나빠지는 것과 도움이 줄어드는 것은 여기가 아니라 대사가 정합니다.**
움직임을 끈 경우에는 3·4단계만 색으로 남습니다.

`voice: "self"` 는 **채점 결과의 화자를 바꿉니다.** 종장에서만 씁니다.
평소에는 실패 이유가 전부 Aistb 말풍선을 지나가는데(`finishReport`), 종장에서는 Aistb 가
도와주지 않는 것이 그 장의 내용이라 그 화자를 쓸 수 없습니다.

| | 평소 | `voice: "self"` |
|---|---|---|
| **채점 실패** | Aistb 말풍선 (`tone: "bad"`) | **독백** (`js/self.js`, 화면 왼쪽 아래) |
| 그 밖의 전부 | Aistb | **Aistb 그대로** |
| 업무 메뉴 | 의뢰 확인 · 완료 보고 · 지금 할 일 다시 듣기 | 목표 확인 · **Aistb 수리** · 지금 할 일 다시 보기 |

**독백이 나오는 곳은 채점이 틀렸을 때 하나뿐입니다.** 실행 에러도 자리비움도 Aistb 가 맡습니다.
드물게 나와야 나올 때 무겁습니다. 종장의 이야기는 beat 의 `lines` 와 그날 일기가 끌고 갑니다.

beat 의 `menu: ["repair"]` 가 「Aistb 수리」 항목이고, `report` 와 하는 일이 같습니다.
파일에 `kind: "goal"` 을 주면 탐색기에 「목표」 배지가 붙습니다(`kind: "brief"` 는 「의뢰서」).

**말풍선은 종장에도 그대로 있습니다.** Aistb 가 사라지는 것이 아니라 도움이 되지 않는 것이고,
그 대사는 여전히 beat 의 `lines` 로 씁니다. 화면 오른쪽 아래에서 극찬과 헛소리를 하고
왼쪽 아래에서 혼자 생각하는 모양이 됩니다.

> 말풍선과 독백은 각자 화면을 덮는 가림막을 깝니다. **둘이 동시에 뜨면 안 됩니다** —
> 겹치면 화면이 두 배로 어두워집니다. 서로의 것을 걷어내게 해 두었으니 새 화자를 더할 때도
> 같은 것을 지켜야 합니다.

하루치 진행은 `beats` 배열이 정합니다. 한 beat은 이렇게 돌아갑니다.

| 칸 | 하는 일 |
|---|---|
| `lines` | Aistb가 할 말. 문자열이거나 `{ who, text, tone, spot }`. **플레이어가 눌러야** 다음 줄로 갑니다 |
| `spot` | 말하는 동안 가리킬 곳. Aistb가 그 옆으로 이동하고 대상에 테두리가 생깁니다 |
| `addFiles` | 이 beat에서 도착하는 파일. 의뢰가 여러 건인 날은 이걸로 하나씩 내려줍니다 |
| `report` | 이 beat의 완료 보고 검사. **약속(Promise)을 돌려줘도 됩니다** |
| `wait` | 이 함수가 참이 될 때까지 기다립니다. 없으면 말이 끝나는 대로 다음 beat |
| `menu` | 이 beat에서 열어줄 업무 메뉴 — `"brief"`, `"report"`, `"end"` |
| `reject` | 잘못한 것이 있으면 그 이유를 돌려줍니다. 같은 말을 반복하지는 않습니다 |
| `nudge` | 한참 조작이 없을 때 대신 할 말 |

`wait(ctx)`의 `ctx`에는 `reported`, `ended`가 들어 있어 메뉴를 눌렀는지 볼 수 있습니다.

> **`wait`가 보는 상태를 새로 만들 때는 그 자리에서 `IDE.onChange()`를 불러야 합니다.**
> 조건은 `IDE.onChange` / `IDE.onRun` 이 불릴 때만 확인합니다. 화면만 다시 그리고 알리지 않으면,
> 조건이 이미 채워졌는데도 다음 조작이 있을 때까지 넘어가지 않습니다.
> 중단점 찍기와 폴더 고르기가 실제로 이 문제로 멈춰 있었습니다.
`report()`는 완료 보고를 눌렀을 때 부릅니다 — **문제가 있으면 그 이유를 문자열로**, 괜찮으면 `null`.
그 문자열이 그대로 Aistb의 말이 됩니다.

### 하루의 종류 — 배우는 날과 푸는 날

챕터 하나가 하루입니다. 둘만 예외로, 2·3장이 10/3 하루의 오전·오후이고
4·5장이 10/6 하루의 오전·오후입니다(근무일을 달력에 맞추느라 그렇습니다).
반나절로 끊는 날은 「업무 종료」 자리에 `endLabel: "점심"` 을 답니다.

하루는 셋 중 하나만 합니다.

| 종류 | 하는 일 | 예 |
|---|---|---|
| **배우는 날** | 참고 문서 + 예제 파일 + 실습 과제. 의뢰는 하나도 오지 않습니다 | 1장(NumPy), 4장(Pandas·오전) |
| **푸는 날** | 새로 배우는 것 없이 배운 것으로 의뢰만 처리합니다 | 2장(오전), 5장(Pandas·오후) |
| **섞인 날** | 연습·익힘으로 배운 뒤 그날의 의뢰를 그것으로 처리합니다 | 3장(오후), 6~8장 |
| **큰 건** | 새로 배우는 것 없이, 한 사람의 의뢰 하나를 처음부터 끝까지 혼자 끌고 갑니다 | 9장 |

6장부터는 연습날에도 의뢰서가 옵니다. 세계관이 새어 나오는 자리가 의뢰서의 「비고」 칸
하나뿐이라, 의뢰서가 없는 날이 있으면 그 노출이 끊깁니다(`feed-back.md`).
그래서 배우는 날의 익힘 뒤에 그날 배운 것으로 푸는 의뢰 한 건을 붙입니다.

**푸는 날에는 코드를 깔아주지 않습니다.** 오는 것은 의뢰서 하나뿐이고, 폴더와 파일은
플레이어가 직접 만듭니다. 그래서 의뢰서에 이 셋이 반드시 들어갑니다 — 자료(손으로 칠 수 있는
크기로), 만들 파일의 경로, 답을 담을 변수 이름. 채점 코드도 자료 변수 이름에 기대지 않고
**답의 값만** 봅니다(정답 값을 채점 코드 안에 적어 둡니다).

빈칸을 채우는 것과 빈 파일에서 시작하는 것은 남는 것이 다릅니다. 배우는 날의 연습·실습 파일은
빈칸을 주고, 푸는 날은 빈 파일에서 시작합니다.

배우는 날의 참고 문서는 `NUMPY_DOC` / `PANDAS_DOC` 처럼 변수 하나로 두고, 다음 날 챕터가
`desk.files` 에 같은 것을 다시 깔아 줍니다. 챕터가 바뀔 때 파일 시스템이 비워지기 때문입니다.

배우는 날은 `개념 → 익힘 → 개념 → 익힘 …` 으로 가고, 푸는 날은
`의뢰 도착 → 작업과 완료 보고 → 접수` 를 의뢰 수만큼 반복합니다.

**하루의 크기는 한 자리에서 끝낼 수 있는 만큼입니다.** 일차는 분량을 담는 그릇이 아니라
호흡을 끊는 장치라서, 내용이 많으면 일차를 늘립니다. 대략의 기준은 대사 15~25줄,
직접 채워야 할 답 5~11개, 익힘 6문제 안팎(대략 10~15분)입니다. 지금 1장만 그 두 배입니다.

### 사용법을 가르치는 방식

배우는 날이 쓰는 형식입니다. 새 도구를 쓰게 하기 전에 반드시 이 순서를 지킵니다.

1. `work/참고/○○_요약.md` 를 내려주고 **오른쪽 화면에 펼칩니다**(`addFiles` 의 `open: 1`).
   함수 하나에 한 줄 설명이 붙어 있고, 하루가 끝나도 파일로 남습니다.
   **참고 문서와 의뢰서에는 `**굵게**` 가 먹지 않습니다.** 읽기 전용 파일은 글자 그대로
   그려지고(`js/ide.js`), `# ` 로 시작하는 줄만 제목이 됩니다. 굵게가 되는 곳은 Aistb 대사뿐입니다.
2. `work/예제/○○.py` 를 내려주고 **한 문장씩 실행**하게 합니다(`↓ 한 줄`).
3. **출력이 먼저, 설명이 나중입니다.** 방금 화면에 나온 것을 Aistb가 짚어주고, 그때
   참고 문서의 해당 항목을 `spot` 으로 가리킵니다(`spot: { text: "arr[1:3]", in: ".doc" }`).
   설명이 결과보다 앞서면 순서가 틀린 것입니다.
4. 그 다음에 **실습 과제**를 내줍니다. 방금 본 것을 그 자리에서 한 번 직접 풀어봅니다.
5. 같은 함수를 쓰는 의뢰는 **다음 날(푸는 날)** 에 도착합니다.

진행 조건은 `steppedTo(경로, n)` 으로 씁니다 — "그 파일에서 n번째 문장까지 실행했는가".
문장 경계는 파이썬의 `ast` 가 잡으므로 여러 줄에 걸친 문장도 하나로 셉니다.

설명하는 beat에는 `show: [{ path: "work/참고/numpy_요약.md", pane: 1 }]` 를 붙여 두세요.
그 사이 다른 문서(의뢰서 등)가 오른쪽에 올라와 있으면 `.doc` 이 그쪽을 가리켜 하이라이트가 빗나갑니다.

### 실습 과제 — 빈칸을 채우고 완료 보고로 채점합니다

`content/ch01.js`에 도구가 있습니다. `work/실습/○○.py` 에는 빈칸(`... `)만 둡니다 —
**정답도 채점기도 플레이어가 여는 파일에는 넣지 않습니다.** 채점은 `drillCheck([[이름, 정답], …])`
가 만든 코드를 `checkFile(경로, 채점코드)` 로 파일 밖에서 돌려서 합니다(아래 "제출한 코드
채점하기"와 같은 길). beat 에 `menu: ["report"]` 를 주고, 플레이어가 완료 보고를 누르면
이름별로 순서대로 보다가 처음 틀린 곳을 짚어줍니다. 진행 조건은 `ctx.reported` 입니다.

`drillCheck` 는 `np.array_equal(np.asarray(…))` 로 값을 견주므로 배열·판다스 Series·스칼라를
모두 그대로 받습니다. 틀렸을 때 지금 값은 보여주되 정답은 알려주지 않습니다.

### 제출한 코드 채점하기

`content/ch01.js`의 `checkFile(경로, 채점코드)`를 쓰면 플레이어가 쓴 파일을 실제로 돌린 뒤
`assert` 로 확인합니다. **실패한 assert의 메시지가 그대로 Aistb의 말이 됩니다.**

```js
report: function () {
  return checkFile("work/task_02/fee.py",
    "assert np.allclose(fee, distance * 1500 + 2000), f'값이 다릅니다. 지금 {fee} 입니다.'");
}
```

확인하는 동안 Aistb가 "확인하고 있습니다…"라고 말하고 완료 보고 항목이 잠깁니다.
`import` 는 자동으로 읽혀서 필요한 라이브러리(numpy, pandas 등)를 알아서 가져옵니다 —
`packages` 를 따로 적을 필요가 없습니다.

### 가리키기(spot)

두 가지 형태를 받습니다.

```js
spot: ".run"                                  // 화면 요소 하나
spot: '.tree-row[data-path="work/의뢰_0001.md"]'
spot: { text: "first_task", in: ".doc" }      // 글 안의 특정 문장이나 단어
```

문장 단위는 그 대목을 감싸서 표시합니다. 다만 `textarea`(코드 편집창) 안의 글자는 감쌀 수 없어
대상이 되지 않습니다. 화면을 다시 그려도 가리키던 곳은 자동으로 복원됩니다.

## 눈높이 — 대본을 쓸 때의 기준선

**독자는 파이썬 리스트와 for문은 써봤지만 그 외에는 아무것도 모르는 초등학교 6학년**이라고 놓고 씁니다.
파이썬을 안다고 해서 수학이나 영어 용어를 안다는 뜻이 아닙니다.

- 새 이름은 **겪게 한 다음에 붙입니다.** 설명이 먼저 나오면 순서가 틀린 것입니다.
- 말로만 설명하지 말고 `spot`으로 가리키고, 되도록 플레이어가 직접 눌러보게 합니다.
- 한자어 대신 눈에 보이는 말을 씁니다 — "음수"보다 "마이너스".
  **표의 가로세로만 예외로 "행/열"을 씁니다.** "칸"은 표의 한 자리(cell)로 읽혀서
  열이라는 뜻이 전해지지 않습니다. `줄별/칸별` 이 아니라 `행별/열별`,
  방향("행 방향")이 아니라 `열별 평균(axis=0)` / `행별 평균(axis=1)` 로 적습니다.
- 한 대사에 한 가지만 담습니다. 두 가지를 말해야 하면 대사를 둘로 나눕니다.
- 용어는 챕터를 넘어 하나로 통일합니다(예: `비용`과 `cost`를 섞어 쓰지 않습니다).
- 미분처럼 아직 안 배운 것이 필요하면 **식을 그냥 주고 옮겨 적게 한 뒤** 나중 챕터에서 갚습니다.

채점이 있는 단계를 만들 때는 **흔한 오답이 우연히 통과하지 않는지** 반드시 같이 돌려보세요.
